# 다른 PC용 공단 EDI 병렬 실행 환경 준비 가이드

> 기준일: 2026-08-10 · 실기기 병렬 처리 검증: v1.1.6 · 사전점검 기능: v1.1.10
>
> 이 문서는 공단 EDI 병렬 메뉴(국민연금·국민건강보험·고용보험)를 새 PC에서 처음
> 실행하기 전에 필요한 환경과 첫 실행 절차를 정리한다. 인증서·비밀번호·기존 PC의
> Chrome 프로필은 옮기지 않는다.

## 1. 결론 요약

현재 기준 PC에서는 다음 조합으로 선택 수임처 1건의 세 기관 다운로드가 모두
성공했다.

| 항목 | 검증 기준 | 다른 PC에서의 처리 |
|---|---|---|
| 운영체제 | Windows 10 Enterprise 64비트, 10.0.19045 | Windows 10/11 64비트에서 스모크 테스트 권장. 이 문서의 기준 PC는 Windows 10이다. |
| 브라우저 | Google Chrome stable 151.0.7922.77 (x86 설치) | 정확히 같은 버전으로 고정하지 말고 최신 stable Chrome을 설치한다. Edge·웨일·Brave는 사용하지 않는다. |
| 앱 | 원천징수 자동화 v1.1.6에서 세 기관 병렬 처리 성공, v1.1.10에 사전점검·안정화 안내 반영 | v1.1.10 이상 최신 빌드를 설치한다. |
| Python/Playwright/Node | 별도 설치하지 않음 | 앱 번들에 포함되어 있으므로 설치하지 않는다. Playwright용 Chromium도 필요 없다. |
| 환경변수 | `WTAX_*` 수동 설정 없음 | 설정하지 않는다. 디버그용 변수는 지원 담당자 지시가 있을 때만 사용한다. |
| 보안 프로그램 | 포털 공식 설치 화면에서 설치 | 다른 PC에 기존 프로그램/레지스트리/Chrome 프로필을 복사하지 않는다. |

앱 설치 파일은 약 169 MB, 설치 후 앱 번들은 약 406 MB였다. Windows 업데이트,
다운로드 결과와 보안 모듈 설치 공간을 고려해 **여유 디스크 1 GB 이상**을 권장한다.

## 2. 필수 조건

### 반드시 준비할 것

- **Google Chrome stable**이 설치되어 있고 한 번 이상 실행된 상태
- 앱을 실행할 **동일 Windows 계정**에서 접근 가능한 공동인증서와 각 포털의 업무 권한
- 인터넷 연결과 다음 포털 HTTPS 접속 가능 상태
  - `https://edi.nps.or.kr/`
  - `https://edi.nhis.or.kr/`
  - `https://total.comwel.or.kr/`
- 바탕화면에 결과 폴더를 만들 수 있는 쓰기 권한
- 포털 보안 모듈 설치 시 UAC 또는 사내 보안 정책 승인을 받을 수 있는 환경

### 설치하지 않아도 되는 것

- Python, pip, Node.js, Playwright, Playwright 브라우저 바이너리
- ChromeDriver 또는 별도 WebDriver
- WehagoNTS (공단 EDI 다운로드만 사용할 때는 불필요하며, WEHAGO 전자신고 기능용이다)
- `WTAX_CDP_PORT`, `WTAX_FRESH_PROFILE`, `WTAX_SEPARATE_USER_DATA` 등의 환경변수

## 3. 병렬 EDI가 만드는 전용 Chrome 환경

병렬 메뉴는 일반 Chrome 창 하나를 공유하지 않는다. 실행 사용자별
`%LOCALAPPDATA%\원천징수자동화-data\chrome-profiles` 아래에 세 개의 **별도 영속
프로필**을 만들고, 각 포털을 다른 localhost CDP 포트로 연다.

| 포털 | 포트 | 전용 프로필 |
|---|---:|---|
| 국민연금 | 9223 | `cdp-9223` |
| 국민건강보험 | 9224 | `cdp-9224` |
| 고용보험 | 9225 | `cdp-9225` |

- 이 포트들은 PC 내부 `127.0.0.1` 연결용이다. 공유기 포트포워딩이나 외부 방화벽 예외를 만들지 않는다.
- 첫 실행이 성공하면 각 프로필에 `.wtax-portal-ready.json` 준비 마커가 생긴다. 이 파일은
  “보안 환경을 한 번 통과함”을 뜻할 뿐, 현재 로그인 세션이 유효하다는 뜻은 아니다.
- 공동인증서와 로그인 쿠키는 민감 정보다. `chrome-profiles` 폴더, 준비 마커, Chrome
  `Preferences` 파일을 다른 PC에 복사하거나 직접 수정하지 않는다.
- 단일 국민건강보험 메뉴는 일반 사용자 Chrome 프로필을 재사용할 수 있지만, **병렬
  건강보험은 항상 `cdp-9224` 전용 프로필**을 사용한다. 따라서 단일 메뉴 로그인 성공이
  병렬 메뉴 로그인 준비까지 대신하지는 않는다.

## 4. 보안 프로그램 설치 원칙

보안 모듈은 사이트·브라우저 버전·사내 보안 정책에 따라 바뀔 수 있다. 현재 기준 PC에
설치된 프로그램 목록을 그대로 맞추는 것이 목적이 아니다. **각 포털이 새 PC에서 표시하는
공식 통합설치/개별설치 화면을 통해 설치**해야 한다.

| 포털 | 공식 설치·안내 | 현재 기준 PC에서 관측된 관련 구성 | 새 PC에서 할 일 |
|---|---|---|---|
| 건강보험 EDI | [공식 Veraport 설치 화면](https://edi.nhis.or.kr/webedi/wizvera/veraportG3/install20/install_pc.jsp) | Veraport, AnySign4PC, AhnLab Safe Transaction, TouchEn 계열, ePageSafer 계열 | 건강보험 전용 Chrome 창에서 통합설치를 실행하고 공동인증서 로그인을 완료한다. |
| 국민연금 EDI | [공식 TouchEn 설치 안내](https://edi.nps.or.kr/raonnx/install/install_nxkey.html) | TouchEn nxKey 계열 및 Chrome Native Messaging 연결 | 국민연금 전용 Chrome 창의 보안 프로그램·브라우저 확장 설치 안내를 완료한 뒤 새로고침 또는 재접속한다. |
| 고용보험 | [근로복지공단 토탈서비스](https://total.comwel.or.kr/) 로그인 후 안내 | INISAFE CrossWeb EX, SecuKit NX, TouchEn 계열 Native Messaging 연결이 관측됨 | 토탈서비스가 제시하는 설치 안내를 따른다. 필요한 구성은 계정·시점에 따라 달라질 수 있다. |

건강보험 공식 안내에는 Veraport, AnySign, ASTx, TouchEn nxKey/nxWeb,
ePageSafer 같은 모듈이 표시될 수 있다. 이를 임의의 제3자 다운로드 사이트에서 받거나
다른 PC의 레지스트리를 내보내 설치하지 않는다. 포털 공식 설치 화면의 **전체 설치** 또는
해당 오류가 지시하는 개별 설치를 사용한다.

## 5. 앱의 병렬 사전점검 사용 (v1.1.10 이상)

새 PC에서는 실제 업무를 시작하기 전에 GUI 왼쪽 메뉴의 **공단 EDI 병렬 자동화**를
선택하고, 수임처 표 상단 버튼 행의 **맨 오른쪽 [병렬 사전점검]**을 누른다. 이 기능은 아래 항목을
읽기 전용으로 확인한다.

- Google Chrome 탐지, 앱 데이터/바탕화면 저장 위치 권한, 여유 디스크 공간
- 디버그용 `WTAX_*` 환경변수 설정 여부
- 기관별 전용 프로필의 준비 마커
- 국민연금·건강보험·고용보험 HTTPS 연결 가능성

점검은 Chrome을 열지 않고, Chrome 프로필·쿠키·준비 마커·인증서·보안 프로그램을
변경하지 않는다. 따라서 다음 항목은 자동으로 판정할 수 없으며, 첫 실행 중 각 전용
Chrome 창에서 직접 확인한다.

- 공동인증서가 현재 Windows 계정에서 보이는지와 인증서 비밀번호
- 각 기관의 사무대행/사업장 업무 권한
- 포털이 요구하는 보안 모듈 설치 완료와 로그인 세션 유효성

결과 해석은 다음과 같다.

| 상태 | 의미와 조치 |
|---|---|
| `차단` | Chrome을 찾지 못했거나 앱 데이터 저장 위치에 쓸 수 없는 상태다. 해당 항목을 해결한 뒤 다시 점검한다. |
| `확인 필요` | 새 PC의 준비 마커 부재, 네트워크 확인 실패, 바탕화면 권한 등이다. 새 설치에서 준비 마커가 없는 것은 정상이며, 아래 최초 실행 절차에서 해당 기관을 준비하면 된다. |
| `안내` | 최초 실행 때 자동 생성될 앱 데이터 폴더나 공동인증서·업무 권한 직접 확인처럼, 자동화가 아닌 사용자가 판단할 항목이다. |

CDP 포트 9223/9224/9225는 실제 병렬 실행이 시작될 때 앱이 열고 검증한다. 실행 전
사전점검은 포트를 호출하지 않으므로, 아직 실행하지 않은 정상 상태를 경고로 표시하지
않는다. 상세 결과는 GUI 하단 로그에도 남는다.

## 6. 새 PC 설치 절차

1. **Chrome 설치**

   [Google Chrome 공식 페이지](https://www.google.com/chrome/)에서 stable Chrome을
   설치하고, 실제 작업할 Windows 계정으로 한 번 실행한다.

2. **앱 설치**

   검증된 `원천징수자동화_설치.exe`를 실행한다. 앱은
   `%LOCALAPPDATA%\원천징수자동화`에 설치되며 관리자 권한 없이 설치된다.

3. **앱 계정 로그인**

   프로그램을 실행해 발급받은 앱 계정으로 로그인한다. 앱을 관리자 계정으로 설치하고
   다른 일반 계정으로 실행하는 방식은 피한다. 병렬 프로필과 인증서 접근 범위가 사용자
   계정마다 달라질 수 있다.

4. **공동인증서 접근 확인**

   앱을 실제로 실행할 Windows 계정에서 각 공단 로그인에 사용할 인증서가 보이는지
   확인한다. 인증서 비밀번호를 앱이나 문서에 저장하지 않는다.

5. **[병렬 사전점검] 실행 후 공단 EDI 병렬 메뉴를 수임처 1건으로 최초 실행**

   새 프로필이면 GUI 로그에 기관별 최초 준비 메시지가 순서대로 나온다. 열린 창에서
   보안 모듈 설치와 공동인증서 로그인을 직접 완료한다.

   ```text
   국민연금(9223) 준비 → 건강보험(9224) 준비 → 고용보험(9225) 준비
   ```

   세 기관 모두 준비가 끝난 뒤에만 실제 수임처 업무가 세 방향으로 병렬 시작된다.
   준비 중 포털 설치 관리자가 “Chrome을 다시 시작”하라고 하면 앱 실행을 중지한 뒤
   해당 EDI 창을 닫고 안내에 따라 다시 실행한다. 프로필 폴더를 지우지 않는다.

6. **결과 확인**

   병렬 실행의 정상 저장 위치는 다음 구조다.

   ```text
   바탕화면\공단EDI_YYYYMM\{수임처}\국민연금\
   바탕화면\공단EDI_YYYYMM\{수임처}\국민건강보험\
   바탕화면\공단EDI_YYYYMM\{수임처}\고용보험\
   ```

   건강보험 PDF, 국민연금 Excel/PDF, 고용보험 자료를 확인한다. 고용보험 지원금이
   0건이면 지원금 파일이 생성되지 않을 수 있으며, 로그의 “0건 — 스킵 (정상)”이면
   정상 결과다.

## 7. 첫 실행에서 기대할 수 있는 화면과 로그

- 세 개의 Chrome 창이 열리는 것은 정상이다. 각 창은 별도 Chrome 프로필이므로 일반
  Chrome 계정 사진이나 동기화 설정이 보이지 않을 수 있다.
- 프로그램은 `--app`, `--kiosk`, `--headless` 모드로 Chrome을 실행하지 않는다.
  주소창 없는 보안 설치 팝업이 잠시 보이면 포털 보안 모듈 창일 수 있다.
- 준비 마커가 있어도 로그인 쿠키가 만료되면 다음처럼 다시 직접 로그인하라는 로그가
  나올 수 있다. 이는 정상이다.

  ```text
  [NPS] 브라우저에서 국민연금 EDI 로그인을 진행해 주세요.
  [고용] 브라우저에서 근로복지공단(고용보험) EDI 로그인을 진행해 주세요.
  ```

- 실제 병렬 업무가 시작되는 기준 로그는 다음과 같다.

  ```text
  [병렬] 보안환경 준비 완료 — 세 기관 업무를 병렬 시작합니다
  ```

## 8. 장애 시 점검 순서

| 증상 | 먼저 확인할 것 | 하지 말 것 |
|---|---|---|
| 한 기관만 열리지 않음 | GUI의 `[병렬 준비]`, `bootstrap 실패`, `exit=`, `port=` 로그 | 준비 마커를 직접 만들거나 세 프로필을 복사 |
| 로그인 대기에서 멈춤 | 해당 전용 Chrome 창에서 올바른 인증서·업무 권한으로 로그인 | 다른 포털 창을 닫거나 인증서 비밀번호를 공유 |
| 보안 프로그램 설치가 반복됨 | 포털 공식 설치 화면에서 설치 상태 확인 → 사이트 안내에 따라 Chrome 재시작 | 인터넷의 구버전 설치 파일·레지스트리 import 사용 |
| 빈/주소창 없는 창이 보임 | 창을 닫기 전 전체 화면과 GUI 로그를 캡처 | 실행 중인 프로필 폴더·`SingletonLock`을 강제 삭제 |
| 앱은 완료인데 파일이 없음 | `공단EDI_YYYYMM` 아래 포털별 하위폴더와 기관별 결과 요약 | 단일 실행 폴더만 확인하고 병렬 결과를 누락 판단 |

지원 요청에는 아래 항목만 전달한다. 인증서 파일, 비밀번호, 주민등록번호, 사업장관리번호,
Chrome 프로필 파일은 전달하지 않는다.

- 앱 버전, Windows 버전, Chrome 버전
- 실행 시각과 선택 건수
- `[병렬 준비]`부터 완료/실패까지의 GUI 로그
- 문제가 열린 상태의 전체 화면 스크린샷
- `%LOCALAPPDATA%\원천징수자동화-data\logs\lifecycle.log`의 해당 시각 줄

## 9. 검증 완료 기준

새 PC에서 아래 네 항목을 모두 만족하면 병렬 EDI 환경 준비가 완료된 것으로 본다.

1. 국민연금·건강보험·고용보험 전용 프로필의 최초 준비가 모두 성공한다.
2. 수임처 1건에서 세 기관의 업무가 모두 시작되고, GUI 결과가 모두 완료로 표시된다.
3. `공단EDI_YYYYMM` 아래 세 포털 하위폴더에서 기대 파일 또는 정상 0건 로그를 확인한다.
4. 앱을 재시작해도 준비 단계가 불필요하게 반복되지 않으며, 세션 만료 시에는 각 포털의
   로그인 안내를 따라 다시 로그인할 수 있다.
